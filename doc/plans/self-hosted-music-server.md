## 一、背景与目标

- 拾音（lx-music-mobile 定制版）当前取链依赖社区公益音源脚本：不可控、随时失效。
- 目标：自建取链服务端（自有 QQ/网易云会员凭证），App 内置直连，激活码付费授权，随 App 分发。
- 商业定位：**收费运营**（经营性，风险见 §七）。

## 四、服务端方案要点

- 部署：docker 容器跑 lx-music-api-server + Redis，只绑内网（对齐净屏 172.20.0.x 模式），nginx-gateway 反代 + TLS。
- 接口面：`POST /register`（激活码+设备指纹→token+device_secret）、`GET /config`（源开关子集+音质档位）、`GET /url/{source}/{songId}/{quality}`（token+HMAC）。
- 凭证配置：网易 MUSIC_U + QQ 登录 cookie，从自己登录态提取；失效监控（连续失败计数）→ 自动摘源+告警。
- 支付/发码：虎皮椒 → 发卡 → 码入库（复用 license-platform 表结构思路）。

## 七、风险存档（已知情拍板）

1. **版权/合规**：收费提供音乐解析 = 经营性侵权，风险较免费分享质变；阿里云境内机 + 备案域名同机混部，被投诉有连坐净屏业务可能（缓解：容器隔离、独立域名考量）。
2. **维护接力**：平台接口变动（尤其 QQ）需自己跟进适配。
3. **cookie 依赖**：会员 cookie 失效即对应源不可用，自动化（§二.9）只能收敛体验，不能消除依赖。
4. **账号风控/封号**（2026-10-20 检索核实，缓解策略已拍板）：api-server 官方 README 免责「封号与本项目无关」；但其 GitHub issues 无一例封号实锤（全是 cookie 过期刷新类），社区实证网页抓取的 QQ cookie 约 3 天失效。后果分层（概率从高到低）：①cookie 加速失效（几乎必然，§二.9 覆盖）→ ②风控升级：滑块/设备指纹/vkey 降级（中期大概率，归 §七.2 维护接力）→ ③音乐账号层限制权益（少见）→ ④QQ 号整体冻结（罕见，纯解析极少触发）。多用户模式单账号高频 vkey 签发 + VPS 单 IP 出口，行为模型不像本人，风险显著高于个人自用。**拍板缓解四条**：①tx 源独立小号开绿钻跑，绝不挂主力 QQ 号（损失上限=会员费，社交资产隔离）；②多账号轮询摊薄单号负载（api-server 支持 tx 多 user 轮询，字段格式以仓库 main.yaml 示例为准）；③服务端 vkey 缓存复用（直链时效几小时，同歌同音质时效内复用砍上游请求量）；④§二.7 的 IP/设备限流兼作对上游的请求量保护。

## 八、下载绑定制共识（2026-10-16 grilling，随激活系统批次实施）

> 触发问题：「做了下载，用户囤歌后不买激活码怎么办」。业界对标核实（2026-10-16）：
> Apple FairPlay/Spotify DRM/QQ mflac-mgg/网易云 ncm——全行业无一例外「下载=会员权益+状态绑定的加密缓存」，
> 无「下载=明文所有权」先例。本节结论：**下载要做，但必须绑定化**；删除不转化为付费
> （lx 生态用户有免费下载途径，需求只会流向竞品），绑定制把下载从蚕食源翻转成续费钩子+离线付费理由。

### 拍板（6 项）

| # | 决策点 | 拍板 |
|---|---|---|
| 1 | 售卖周期 | 按期订阅（年码/月码）（§二.11）——蚕食风险仅在按期制下成立（囤歌退订），买断制无此风险 |
| 2 | 下载形态 | **绑定型下载**：AES 加密存 app 私有目录，仅 app 内可播，退订失效、续订恢复；密钥派生自已拍的 device_secret（§二.7） |
| 3 | 失效语义 | 到期即失效：本地到期时间戳判定（无网也生效，不依赖联网校验），已下载整批置灰；续订后同一批文件无缝恢复可播（无缝恢复本身是续费钩子） |
| 4 | 呈现入口 | 独立「已下载」页=现有下载管理页升级（任务队列+可播列表合一，叠置灰/角标/到期态）；本地音乐页保持纯粹只放设备明文文件；系统媒体库入库废弃 |
| 5 | 播放分流 | 歌单/我喜欢的里播已下载的歌优先播本地绑定文件（离线可播、省流量），未下载照常在线取链；列表项加「已下载」角标；音质升级=重新下载覆盖（同 id 重下=重置语义已有） |
| 6 | 实施排期 | **随激活码系统一并做**（绑定三要素 device_secret/到期日/激活状态全来自激活体系，无激活则只能做无意义的伪绑定中间态）；现版明文下载自用照旧不动 |

### 直接定（效果优先协议，省事版不成案）

- 绑定强度=真加密 AES；「私有目录明文+运行时锁」「轻混淆」为严格劣化省事版，不采用。
- 现有实现三必改：`src/core/download.ts` 的 scanFile 入系统媒体库废弃（加密文件不可暴露给其他 app）、公共目录 `Music/拾音/` 退役、`toDownloadedMusicInfo` 从 local 播放分流改绑定播放分流（含到期置灰）。
- 播放本地解密走本地代理流（业界成熟模式，ExoPlayer 拉 localhost 流）。

### 推论项（随拍板自动成立，无分歧）

- 试用期 3 天可下载、到期自动失效——绑定后试用无蚕食，给完整体验。
- 未激活用户点下载入口=弹激活引导（与播放墙 §二.8 同逻辑；下载需取链，天然在墙内）。
- 每设备独立下载、换设备重新下载——绑定文件物理在本机，跨设备共享缓存无实现路径，业界一致行为。
- 绑定型放弃「导出明文文件上车机/U 盘」能力——业界同款代价（Spotify 同），已知情接受。
- 存量明文下载文件（公共目录现有文件）视为普通本地文件归本地音乐页，不清理。

### 关键事实存档（2026-10-16 核实）

- 取链与播放/下载同链路：`src/core/download.ts` 的 `resolveDownloadUrl` 直接调用 `@/core/music/online` 的 `getMusicUrl`（与播放同一函数、共享 URL 缓存）；vkey 直链时效为几小时量级、每次签发 URL 字面不同，下载失败靠 `runDownloadWithRefresh`（isRefresh 重取）兜底。
- 现版下载页（`src/screens/Download/index.tsx`）已是任务队列+已完成可播列表合一（`toDownloadedMusicInfo` 在用），绑定时只需叠置灰/角标/分流层。
